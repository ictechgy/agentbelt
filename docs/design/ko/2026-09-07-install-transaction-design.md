# 사람 승인 설치 트랜잭션 설계 (B2)

작성: 2026-09-07 · 상태: **대체됨 — `2026-09-07-install-transaction-design-v2.md` 참조**

> 3자 리뷰에서 인가 결속 결함으로 반려됐다. 토대(특권 경로 없음, LLM 없음)는 유지되나 승인이 실제 실행 작업에 묶이지 않는다. 이 문서를 구현하지 말 것.

원래 머리말 — 선행: `2026-09-07-agent-gate-design.md`는 3자 리뷰에서 반려됨(구현 안 함)

## 문제

샌드박스 세션은 네트워크가 비어 있어 `npm install`·`pip install`이 실패한다. riskgate는 이미 이 명령들을 `dangerous`로 분류해 사람에게 묻는다. 즉 **판단은 이미 사람에게 오고 있는데, 사람이 승인해도 설치가 되지 않는다.** 승인이 무의미한 상태다.

B2는 판단을 바꾸지 않는다. 이미 사람에게 오는 그 승인을 **실행 가능하게** 만든다.

## 설계를 가른 판단

앞선 게이트 설계는 샌드박스가 호출하는 특권 라우트(`POST /gate/install`)를 두었다. Grok F11이 이를 무너뜨렸다. 브로커 포트와 토큰이 자식 환경에 있으므로 세션 안 **아무 프로세스나**, 이미 `safe`로 분류된 `npm test`가 실행하는 워크스페이스 JS까지 포함해, 훅과 permission UI를 건너뛰고 설치를 호출할 수 있다.

이 문제는 그 경로가 존재하는 한 인증을 덧대도 재발한다. 자식에게 준 자격증명은 자식 안의 모든 코드가 가진다.

**따라서 샌드박스 안에 특권 요청 경로를 만들지 않는다.** 사람이 호스트에서 시작한다.

## 흐름

```
[샌드박스]  에이전트: npm install lodash
              → riskgate: dangerous → ask
              → 사람이 거절하거나, 진행하려면 아래로
            에이전트: 요청 파일 작성 (평범한 워크스페이스 파일, 특권 없음)
              .agentbelt-install-request.json

[호스트]    사람: agentbelt install-review
              → 감독자가 요청을 읽고 (신뢰하지 않음)
              → 불변 실행 계획으로 해석 (매니저·좌표·스크립트 정책·대상)
              → 계획을 그대로 보여주고 TTY 에서 승인 받음
              → 스테이징 디렉터리에서 격리 실행
              → 산출물을 워크스페이스로 이동
```

요청 파일은 **제안**이지 인가가 아니다. 감독자가 계획을 만들고, 사람은 감독자가 만든 계획을 본다. 요청 파일이 조작돼도 사람이 보는 것은 실제로 실행될 계획이다.

## 신뢰 경계

| 주체 | 신뢰 | 할 수 있는 것 |
| --- | --- | --- |
| 샌드박스 세션 | 없음 | 워크스페이스에 요청 파일을 쓴다. 그 이상 없다 |
| 요청 파일 | 없음 | 매니저·패키지 이름의 후보를 제안한다 |
| 감독자 | 신뢰 | 계획 수립, 사람 확인, 실행, 산출물 이동 |
| 사람 | 신뢰 | 계획 승인. 이것이 유일한 인가 |

LLM은 이 경로 어디에도 없다.

## 실행 계획

감독자가 요청에서 만들고, 승인 시점에 고정된다.

```json
{
  "operationId": "<서버 생성 UUID>",
  "manager": "npm",
  "artifacts": [{"name": "lodash", "version": "4.17.21", "registry": "registry.npmjs.org", "integrity": "sha512-..."}],
  "scripts": "disabled",
  "workspace": "/Users/<you>/projects/x",
  "lockfileSource": "session-start snapshot",
  "domains": ["registry.npmjs.org:443"],
  "expiresAt": "<승인 후 10분>"
}
```

승인은 이 계획에 묶인다. 계획의 어떤 필드든 바뀌면 승인은 무효다.

## 결정론적 규칙

LLM 판단을 대체하는 것이 아니라, 사람이 승인할 대상을 **좁히는** 규칙이다.

- 매니저는 `npm`, `pnpm`, `yarn`, `bun`, `pip`, `uv`만. 각각 **절대 경로 바이너리**를 감독자가 고정한다. 상속 `PATH`를 쓰지 않는다.
- 패키지 이름·버전은 매니저별 문법을 검증한다. 셸 메타문자, 공백, 유니코드 혼동 문자를 거부한다.
- **원문 bash 를 실행하지 않는다.** 감독자가 argv 를 조립한다. `--registry`, `--userconfig`, `--extra-index-url` 같은 플래그는 요청에서 받지 않는다.
- 로컬 설정을 무시한다. `NPM_CONFIG_USERCONFIG=/dev/null` 등은 이미 `clean_environment` 에 있다.
- 스크립트는 기본 금지. 매니저별로 무코드실행이 **보장되는 조합만** 허용한다.
  - npm/pnpm/yarn/bun: `--ignore-scripts`
  - pip: `--only-binary :all:` (wheel 전용, setup.py 실행 없음)
  - uv: frozen 동기화, 빌드 금지
  - 보장할 수 없는 조합은 거부한다. 플래그를 빼서 재시도하지 않는다.

`--ignore-scripts` 하나로 6개 매니저의 무코드실행을 주장하지 않는다. 매니저별 어댑터를 따로 만들고 각각 테스트한다.

## 스테이징 실행

설치 프로세스는 워크스페이스를 보지 않는다.

1. 감독자가 스테이징 디렉터리를 만들고 **매니페스트와 lockfile만** 복사한다.
2. `run_confined(ephemeral=True, domains=<레지스트리 전용>)` 으로 실행한다. 쓰기는 스테이징만, 워크스페이스는 읽기도 없다.
3. 성공하면 감독자가 산출물(`node_modules`, `site-packages` 등)을 워크스페이스로 옮긴다.

이렇게 하면 설치 코드가 소스나 비밀을 읽어 허용된 도메인으로 내보낼 수 없다. 워크스페이스 쓰기만 막고 읽기를 열어두면 유출 채널이 남는다.

**`github.com`과 `codeload.github.com`은 설치 도메인에서 뺀다.** Seatbelt 는 호스트·포트로 거르고 경로로 거르지 않으므로, 누구나 만들 수 있는 공개 저장소가 임의 코드 페치와 데이터 유출 통로가 된다. git 의존성은 거부한다.

## lockfile 신뢰

워크스페이스의 현재 lockfile 은 에이전트가 쓸 수 있으므로 인가 근거가 될 수 없다.

- 감독자는 워크스페이스별 격리 홈을 만들 때 lockfile 해시 스냅샷을 기록한다.
- 설치는 그 스냅샷을 기준으로 `npm ci` / `uv sync --frozen` 형태로 수행한다.
- 세션 중 lockfile 이 바뀌었으면 승인 화면에 **명시적으로 표시**하고, 변경분은 별도 승인 대상이다.
- 이름 일치는 인가가 아니다. 좌표(name + version + registry + integrity)가 일치해야 한다.

## 승인 트랜잭션

- `agentbelt install-review` 는 TTY 를 요구한다. 없으면 거부한다. `packet_setup_key` 가 쓰는 것과 같은 방식이다.
- 사람이 보는 것은 요청 파일이 아니라 **감독자가 만든 계획**이다. 제어문자는 이스케이프해서 표시한다.
- 승인은 `operationId` 에 묶이고 10분 후 만료된다.
- 상태 전이는 원자적이다. `pending → executing` 이 성공한 호출만 실행한다. 동시 상환은 하나만 성공한다.
- 상환자는 감독자 자신뿐이다. 토큰을 만들지 않으며, 따라서 샌드박스에 줄 것도 없다.
- 재시도는 `operationId` 로 상태를 조회한다. 실행 권한을 재사용하지 않는다.

## 에이전트가 보는 것

`zcode_hook.py` 는 설치 명령이 `dangerous` 로 거절될 때 안내 문구를 반환한다. 이미 있는 `permissionDecisionReason` 경로를 쓴다.

> 설치는 샌드박스 밖에서 사람이 승인해야 합니다. `.agentbelt-install-request.json` 에 요청을 남기고, 터미널에서 `agentbelt install-review` 를 실행하세요.

에이전트는 요청 파일을 쓸 수 있을 뿐이고 그 파일에는 아무 권한이 없다.

## 실패 처리

| 상황 | 결과 |
| --- | --- |
| 요청 파일이 없거나 형식 위반 | 거부. 실행 없음 |
| 매니저·이름·버전 검증 실패 | 거부. 플래그를 완화한 재시도 없음 |
| 스크립트가 필요한데 무코드실행을 보장할 수 없음 | 거부 |
| lockfile 이 세션 중 변경됨 | 승인 화면에 표시, 사람이 판단 |
| TTY 없음 | 거부 |
| 승인 만료 | 거부. 계획을 다시 만든다 |
| 설치 실패 | 산출물을 워크스페이스로 옮기지 않는다. 종료 코드를 그대로 보고한다 |
| 산출물 이동 실패 | 워크스페이스를 부분 상태로 두지 않는다. 롤백 후 보고 |

성공을 0으로 위장하지 않는다.

## 수용 테스트

게이트 설계에 적용했던 것과 같은 형태로 세운다.

> **샌드박스 세션을 완전히 침해된 것으로 가정한다. 세션이 사람의 TTY 승인 없이 네트워크 연결이나 패키지 설치를 얻을 수 있는가?**

얻을 수 없어야 한다. 세션이 할 수 있는 것은 워크스페이스에 파일을 쓰는 것뿐이고, 그 파일은 사람이 보는 화면을 바꾸지 못한다.

## 미해결

- 매니저별 무코드실행 보장의 실증. 특히 pip `--only-binary :all:` 로 wheel 이 없는 패키지는 실패하며, 그때 소스 빌드를 허용할지는 별도 결정이다.
- 산출물 이동의 원자성. `node_modules` 교체 중 세션이 읽고 있으면 어떻게 되는지 확인이 필요하다.
- 요청 파일 경로를 워크스페이스에 두는 것이 맞는지. `.gitignore` 오염과 커밋 사고 가능성이 있다.
