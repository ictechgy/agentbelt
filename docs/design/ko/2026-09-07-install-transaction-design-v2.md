# 설치 트랜잭션 설계 v2 — 승인된 좌표만

작성: 2026-09-07 · 상태: 검토 대기 · 대체: `2026-09-07-install-transaction-design.md` (3자 리뷰 반려)

v1 은 토대는 유지됐으나 인가 결속에서 반려됐다. 리뷰 종합: `../reviews/2026-09-07-install-transaction-consensus.md`.

v2 의 범위를 **신규 좌표 추가 하나**로 좁혔다. 이 결정 하나가 v1 결함의 절반을 제거한다. 워크스페이스 파일을 읽지 않으므로 매니페스트 복사, 스냅샷 위조, 복사 시 심볼릭 링크 리다이렉트, 입력 TOCTOU 가 성립하지 않는다.

## 성질

v1 의 수용 테스트는 문구가 틀렸다. 세션은 워크스페이스 쓰기만으로 이미 `node_modules` 에 파일을 심을 수 있으므로 "설치를 얻을 수 없다"는 거짓이다. 다시 쓴다.

> **세션은 사람이 그 정확한 트랜잭션을 승인하지 않는 한, 호스트가 대신하는 페치·설치·게시를 유발할 수 없다.**

여기에 v1 리뷰가 요구한 두 번째 성질을 더한다.

> **승인은 실제로 실행되는 작업에 묶인다.** 사람이 화면에서 본 좌표 집합과 워크스페이스에 게시되는 산출물이 정확히 일치한다.

## 범위

**하는 것:** 사람이 승인한 좌표(`name`, `version`, `registry`, `integrity`)와 그 의존성 폐포를 워크스페이스에 설치한다.

**안 하는 것:** lockfile 재생·프로젝트 복원, 워크스페이스 매니페스트 해석, git 의존성, 소스 빌드, 회색지대 프롬프트 축소(B1 별건).

## 워크스페이스 입력 없음

이 설계의 중심 규칙이다.

- 워크스페이스의 `package.json`·`package-lock.json`·`pyproject.toml`·`requirements.txt`·`uv.lock`·`.npmrc`·`.yarnrc.yml`·`bunfig.toml`·`.pnpmfile.cjs` 를 **읽지 않고 복사하지 않는다.**
- 스테이징 매니페스트는 승인된 좌표만으로 **합성**한다.
- 요청 파일은 사람에게 보여줄 **후보 이름**만 제공한다. 그 안의 다른 필드는 무시한다.

v1 은 "요청에서 `--registry` 플래그를 받지 않는다"고 쓰고도 같은 힘을 가진 매니페스트를 실행했다. v2 는 그 입력 경로 자체를 없앤다.

## 흐름

```
[샌드박스] 에이전트: npm install lodash
             → riskgate: dangerous → 훅은 deny + 안내
             → (선택) 워크스페이스에 후보를 적은 요청 파일

[호스트]   사람: agentbelt install npm lodash@4.17.21
             1) 좌표 확인      사람이 이름과 버전을 직접 지정하거나 후보에서 고른다
             2) 해석 승인      "registry.npmjs.org 에 이 좌표의 메타데이터를 물어봐도 되는가"
             3) 폐포 표시      해석된 전체 의존성 목록 + integrity
             4) 설치 승인      화면의 확인 문구를 그대로 입력해야 진행
             5) 격리 실행      워크스페이스 접근 없는 스테이징
             6) 검증 후 게시   계획에 없는 항목·탈출 링크가 있으면 폐기
```

승인이 두 번인 이유는 3절에 있다.

## 승인 채널

`isatty()` 는 인증이 아니다. PTY 로도 만족되고, 에이전트가 터미널 인프라를 제어하면 합성 입력이 가능하다.

- **확인 문구.** 4단계에서 감독자가 무작위 단어를 화면에 출력하고, 그것을 그대로 입력해야 진행한다. 터미널에 입력을 주입할 수 있어도 **화면을 읽지 못하면** 통과하지 못한다. 이것이 이 설계의 실질적 사람 증명이다.
- 승인 입력은 요청 파일·명령 인자·환경에서 읽지 않는다. 오직 그 터미널의 입력에서만 읽는다.
- **세션 UI 승인은 설치를 점화하지 못한다.** riskgate 가 `dangerous` 로 올린 세션 permission 승인은 세션 안 실패(네트워크 없음)로만 이어진다. 훅은 설치 패턴에 `deny` + 안내를 반환한다. `permissionDecision=allow`, OpenCode `status:"allow"`, `zcode-shell` 어느 것도 설치를 시작하지 못하는 것을 테스트로 고정한다.
- `development.json` 의 `packageDomains` 는 v2 가 채우지 않는다. 세션 프로파일은 그대로 비어 있다.

**남는 위험:** 승인 터미널이 에이전트가 제어할 수 없는 것임을 이 설계가 증명하지는 못한다. 확인 문구가 그 간극을 좁히지만 없애지는 않는다.

## 해석 단계

신규 좌표는 버전과 integrity 를 알아야 계획이 된다. 그 정보는 레지스트리에 있으므로 **승인 전에 네트워크가 필요하다.** v1 은 이 단계를 정의하지 않아 공격자가 고른 요청이 사람 승인 없이 나갈 수 있었다.

v2 는 이를 별도 승인으로 만든다.

- 사람이 좌표를 지정하거나 후보를 고른 뒤, "이 이름에 대해 레지스트리에 물어본다"를 승인한다.
- 해석은 격리 실행으로, **허용된 레지스트리 호스트의 메타데이터 엔드포인트에만**, 리다이렉트 없이, 크기 상한을 두고 수행한다.
- 결과는 전체 의존성 폐포다. 사람은 그 목록 전체를 보고 설치를 승인한다.
- 해석이 실패하거나 폐포에 허용되지 않은 출처(`git:`·`file:`·`link:`·`workspace:`·`http:`·비허용 레지스트리)가 있으면 거부한다.

`install-review` 를 시작하는 것 자체가 임의 해석 트래픽의 승인이 되지 않는다.

## 실행

- 매니저 실행 파일은 **고정 절대 경로**이며 감독자가 소유·보호한다. 상속 `PATH` 를 쓰지 않는다.
- 환경은 허용목록이다. 설정·캐시·홈을 매 실행 새로 만든다. 프로젝트가 고르는 툴 버전·자격증명 헬퍼 등 암묵적 탐색을 끈다.
- 스테이징은 합성 매니페스트와 승인된 폐포만 담는다. **워크스페이스는 읽기도 쓰기도 없다.**
- 아웃바운드는 호스트가 아니라 **요청** 단위로 제한한다. 승인된 아티팩트 엔드포인트, 메서드, 리다이렉트 금지, 헤더·크기 상한. npm audit 등 요청하지 않은 트래픽을 끈다.
- `github.com`·`codeload.github.com` 은 설치 도메인이 아니다.

### 매니저별 무코드실행

**버전 × 명령 × 입력형식 × 설정 × 런타임** 조합을 명시하고 각각 적대적 테스트를 붙인다. 미지의 조합은 비활성이며, 플래그를 빼서 재시도하지 않는다.

| 매니저 | 알려진 함정 |
| --- | --- |
| npm | `--ignore-scripts` 는 패키지 스크립트만. 프로젝트·사용자·전역·내장 설정 소스가 별도로 있다 |
| pnpm | pnpmfile 등 실행 가능한 설정 훅을 배제해야 한다 |
| Yarn | Berry 는 `--mode=skip-build`. 메이저 버전과 linker 를 고정하고 플러그인을 배제한다 |
| bun | `trustedDependencies` 경로가 남는다 |
| pip | wheel 전용은 sdist 빌드만 막는다. `.pth` 는 인터프리터 시작 시 실행되므로, 설치된 환경으로 호스트 인터프리터를 띄우지 않는다 |
| uv | `--no-build` 는 first-party·editable 빌드를 여전히 허용한다. 명시적으로 거부한다 |

## 게시

산출물 이동은 감독자(제한 없음)가 하므로 v1 에서 가장 위험한 단계였다.

- 검증된 디렉터리 핸들에 고정하고 **링크를 따르지 않는** 연산만 쓴다.
- 출력 트리를 먼저 검증한다. 승인된 폐포에 없는 패키지, 트리 밖을 가리키는 링크, 특수 파일이 있으면 **게시하지 않고 폐기**한다.
- 부분 병합이 아니라 완성된 세대를 한 번의 전환으로 게시한다.
- 게시·롤백·삭제에 같은 링크 보호를 적용한다.
- 워크스페이스별로 게시를 직렬화한다.

## 상태와 복구

- 트랜잭션 저널과 스테이징은 **세션이 접근할 수 없는 곳**에 둔다. `state/homes/*` 는 Seatbelt `allowWrite` 이므로 사용하지 않는다.
- 승인 결속과 소비를 실행 전에 영속화한다. `pending → executing` 은 원자적이다.
- 종료 상태·취소·만료·프로세스 트리 종료·불명 결과 복구를 정의한다. 불명확한 소비 완료 작업을 자동 재실행하지 않는다.
- 설치 성공 종료 코드는 설치 성공의 증거가 아니다. 검증을 통과해야 게시한다.

## 유출에 대한 정직한 기술

"유출 없음"이라고 쓰지 않는다.

세션이 비밀을 패키지 이름·버전에 인코딩하면, 사람이 그 좌표를 승인하는 순간 레지스트리로 전송된다. 확인 문구와 폐포 표시가 이를 사람 눈에 노출시키지만, 사람이 긴 목록을 정독하지 않으면 통과할 수 있다. **한정된 공개**이며 남는 위험이다.

완화: 좌표 표시에 제어문자를 이스케이프하고, 비정상적으로 긴 이름·비ASCII·base64 형태를 경고 표시한다.

## 미해결

- 확인 문구가 실제로 어떤 터미널 자동화를 막는지 실측하지 않았다.
- 해석 단계의 폐포 계산을 매니저별로 어떻게 오프라인 검증 가능한 형태로 얻을지 정하지 않았다.
- 게시의 원자성. `node_modules` 세대 전환 중 세션이 읽고 있을 때의 동작.
